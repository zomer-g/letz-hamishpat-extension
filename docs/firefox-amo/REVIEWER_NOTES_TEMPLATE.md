────────────────────────────────────────────────────────────────────────────
1. WHAT THE ADD-ON DOES
────────────────────────────────────────────────────────────────────────────
Israel's court system ("נט המשפט" / Net HaMishpat) lets a litigant or lawyer
view case materials one document at a time. This add-on adds a panel to those
pages so the user can tick several documents or hearings and export them in one
action:

  • documents  → one ZIP containing a PDF per document plus a CSV index,
                 or the site's own native Word export
  • hearings   → CSV + ICS, and optionally synced into a Google Calendar
                 the user picks

All of it runs in the user's own authenticated tab, against the court site's
own endpoints. The add-on has no server of its own, no analytics, and no
telemetry of any kind.

────────────────────────────────────────────────────────────────────────────
2. HOW TO EXERCISE IT WITHOUT AN ISRAELI LOGIN
────────────────────────────────────────────────────────────────────────────
The authenticated portal needs an Israeli national-ID or smart-card login,
which a reviewer cannot obtain. It is not needed: the SAME features run on the
PUBLIC, no-login portal. Steps:

  1. Open  https://www.court.gov.il/NGCS.Web.Site/HomePage.aspx
  2. In the header, "מספר תיק" (case number), enter case number 30638 and
     month-year 12-25, then press "אתר" (locate). This is a real, public case.
  3. The case opens. In the right-hand tree choose:
       • "החלטות בתיק"  (decisions)     → the document panel appears
       • "מועדי דיון"   (hearing dates) → the hearings panel appears
  4. Tick a row and press "הורדה" (download). A ZIP is saved locally.

No account, no personal data, nothing is transmitted anywhere except to
court.gov.il — the site the user is already on.

────────────────────────────────────────────────────────────────────────────
3. PERMISSIONS — WHY EACH ONE
────────────────────────────────────────────────────────────────────────────
  host_permissions "https://*.court.gov.il/*"
      The whole point of the add-on. Content scripts read the case grids and
      re-issue the site's own form posts to fetch the documents the user
      selected. Three portals share this domain (public www, and the two
      authenticated ones), which is why it is a wildcard rather than one host.

  host_permissions "https://www.googleapis.com/*"
      ONLY used if the user explicitly connects Google Drive or Google
      Calendar in the options page. Untouched otherwise.

  "identity"
      The Google OAuth flow, same condition — only on explicit sign-in.

  "storage"
      The user's own settings (chosen destinations, filename templates) and
      the resume record of an interrupted download. Local only.

  "activeTab"
      Lets the toolbar popup act on the tab the user is looking at.

There is no "downloads" permission: files are saved with a Blob URL and an
anchor click, which Firefox handles natively.

────────────────────────────────────────────────────────────────────────────
4. GOOGLE SIGN-IN — THE ONE FIREFOX-SPECIFIC PATH
────────────────────────────────────────────────────────────────────────────
Chrome uses chrome.identity.getAuthToken with an `oauth2` manifest block.
Firefox has no such API, so this build uses
browser.identity.launchWebAuthFlow with a Google "Web application" client id,
and the `oauth2` block is removed from the manifest. Capability detection picks
the path at runtime — see background/service-worker.js. Nothing else differs
between the two browsers.

────────────────────────────────────────────────────────────────────────────
NONE of this add-on's own code is minified, obfuscated, transpiled or
generated. Every file we wrote ships as readable source, exactly as authored.

The only minified files are third-party libraries, vendored because MV3 forbids
remote code. Their provenance — and the one place we deliberately changed one of
them — is recorded in src/vendor/VENDOR.json and reproduced here:

{{VENDOR_TABLE}}

Please note the jsPDF entry: we removed its single remote-code loader. jsPDF
injects a <script src="https://cdnjs.cloudflare.com/...pdfobject.min.js"> in its
output('dataurlnewwindow') mode. The extension never calls that mode, and
loading remote code is forbidden by both MV3 and AMO policy, so the URL string
is replaced with an empty string. That is the ONLY byte that differs from the
official release; we verified every other byte is identical.

To confirm for yourself:

    # jszip — identical to upstream (normalise line endings first: a Windows
    # git checkout materialises CRLF, which changes the hash but not the code)
    curl -sL https://unpkg.com/jszip@3.10.1/dist/jszip.min.js | sha256sum
    tr -d '\r' < src/vendor/jszip.min.js | sha256sum        # → same hash

    # jspdf — differs from upstream ONLY at the cdnjs URL described above
    curl -sL https://unpkg.com/jspdf@2.5.1/dist/jspdf.umd.min.js -o upstream.js
    diff <(tr ',' '\n' < upstream.js) <(tr ',' '\n' < src/vendor/jspdf.umd.min.js)

src/tests/vendor.test.js re-checks the recorded hashes against the shipped files
on every test run, so this section cannot silently go stale.

7. WHAT THE BUILD SCRIPT DOES
────────────────────────────────────────────────────────────────────────────
src/build-zip.js walks src/, skips development-only paths (tests/, dist/,
node_modules/, samples/, marketing/, package.json, package-lock.json,
build-zip.js itself and the markdown files) and copies every remaining file
into the ZIP byte-for-byte.

Exactly one file is generated rather than copied: manifest.json.
toFirefoxManifest() takes the Chrome manifest and

  • converts background.service_worker into an event page (background.scripts),
  • adds browser_specific_settings.gecko — the permanent add-on id,
    strict_min_version "140.0", and
    data_collection_permissions { "required": ["none"] } (the add-on collects
    nothing),
  • removes the Chrome-only `oauth2` block,
  • removes `key`, a Chrome-only field kept in source so that a locally loaded
    unpacked copy receives the published extension id during development. It is
    meaningless on Firefox and is stripped from both store packages.

Nothing else is transformed. src/tests/dual-build.test.js pins that contract
and fails the build if the two manifests ever differ in anything else.
